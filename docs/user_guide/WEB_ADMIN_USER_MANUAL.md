# Web 后台使用说明书

## 1. 后台用途

本后台用于内部运营人员管理 AI 客服能力，包括店铺状态、商品知识、SOP、知识发布、人工锁、试聊调试和链路日志。后台第一版面向内部使用，不是面向商家的公网 SaaS。

后台中的试聊、调试、发布验证默认不发送 PDD 消息。真实买家回复仍由既有客服链路负责。

## 2. 页面总览

- 数据总览：查看店铺、消息、AI、知识库和安全状态。
- 店铺接入：通过远程浏览器完成 PDD 登录授权，并启动商品同步。
- 店铺管理：查看店铺基础信息、AI 配置摘要、商品数量和运行状态。
- 商品知识：查看原始商品知识、字段覆盖率、商品详情、RAG chunk 和检索调试。
- 知识中心：维护 SOP 和商品人工知识，并完成发布、索引和生效闭环。
- 人工锁管理：查看和解除指定店铺的人工接管状态。
- 试聊调试：在 no-send 模式下测试 AI 回复和 trace。
- 调试日志：查看历史 AI 回复链路。
- 系统设置：查看服务配置状态，不回显密钥。

## 3. 数据总览怎么用

进入“数据总览”后，先看顶部指标卡片和安全状态。重点关注：

- no-send 是否启用。
- PDD 真实发送是否关闭。
- RAG 索引健康度。
- LLM 错误数和安全拦截数。
- 最近告警。

如果出现大量 LLM 错误、RAG 命中率异常下降或人工锁激增，应先停止扩大流量，进入调试日志和试聊页面排查。

## 4. 店铺管理怎么用

“店铺管理”用于查看已有店铺。可以按店铺 ID、店铺名称、账号状态、WebSocket 状态和 InternalEngine 是否启用筛选。

点击店铺行会打开详情，查看：

- 店铺基础信息。
- InternalEngine 设置摘要。
- 商品知识数量。
- SOP 覆盖情况。
- RAG 索引状态。
- 最近 trace 摘要。

新店铺请优先进入“店铺接入”。“店铺管理”主要用于查看已经接入或已经授权的店铺。

## 4.1 店铺接入怎么用

“店铺接入”用于把 PDD 店铺授权到后台。当前版本统一使用远程浏览器登录，不再提供模拟登录或一次性验证码登录入口。

操作步骤：

1. 进入“店铺接入”。
2. 填写店铺名称和 PDD 账号。
3. 点击“创建登录会话”。
4. 在页面下方远程浏览器窗口中完成 PDD 登录、短信验证码、滑块、扫码或安全验证。
5. 登录完成后点击“我已完成登录，检查状态”。
6. 授权成功后，后台只保存加密授权信息，不展示 cookie/token，也不会保存明文密码。
7. 进入“同步商品”步骤，点击“开始同步商品”。
8. 同步完成后查看成功数、失败数和字段覆盖率。

注意：

- 店铺接入不会发送 PDD 消息。
- 店铺接入不会启动 worker。
- 店铺接入不会启用 AI 自动回复。
- 商品同步只读取商品列表和商品详情，并写入本地 product_knowledge。
- 商品同步不会自动发布知识、不会写 pgvector、不会调用 LLM/Ollama。

## 5. 商品知识怎么用

“商品知识”用于查看从本地数据源读取的商品知识。运营可以查看：

- 商品 ID、商品名、标题、价格、规格、用法、成分、保质期、注意事项。
- 字段覆盖率。
- 原始详情 JSON。
- 当前商品的 pgvector chunks。
- RAG 检索调试结果。

这里展示的是业务调试数据，不展示密钥、token、cookie 或连接串密码。

## 6. 知识中心怎么用

“知识中心”是维护 AI 使用知识的主要入口。它包含四个页签：

- SOP：维护客服 SOP 草稿。
- 商品人工知识：维护商品人工增强字段。
- 版本：查看发布后的不可变快照。
- 索引任务：查看和执行索引任务。

关键规则：

- 保存草稿不会立即生效。
- 发布会生成不可变版本快照。
- 索引成功后，版本才会成为 AI 当前使用的知识。
- Fake index 只用于走通状态机，不写 pgvector。
- Real index 会调用 embedding 服务并写入 pgvector，但不会发送 PDD 消息。

## 7. SOP 发布流程

1. 进入“知识中心 -> SOP”。
2. 新建或选择 SOP。
3. 编辑标题、领域和内容。
4. 点击“保存草稿”。
5. 点击“发布”，生成版本快照和索引任务。
6. 点击“执行 Fake 索引”或在明确需要时执行真实索引。
7. 索引成功后，版本状态变为“当前生效 active”。
8. 到“版本”页签查看 snapshot_json。
9. 到“试聊调试”验证 AI 是否使用新知识。

发布只创建版本和任务，不代表立即生效。

## 8. 商品人工知识发布流程

1. 进入“知识中心 -> 商品人工知识”。
2. 选择店铺和商品。
3. 查看左侧原始商品知识。
4. 编辑人工增强字段，例如用法、注意事项、人工备注、价格备注。
5. 点击“保存人工知识”。
6. 查看“生效预览”，确认字段来源是 raw、manual_override 或 missing。
7. 点击“发布商品知识”，生成商品知识快照和索引任务。
8. 执行索引任务。
9. 索引成功后，新商品版本成为当前生效版本。
10. 用“打开试聊验证”测试价格、规格、用法等问题。

注意：价格字段来自原始商品数据，价格备注只作为补充说明，不覆盖真实价格。

## 9. 版本和索引任务说明

版本是发布时生成的不可变快照。草稿后续修改不会影响已经发布的版本。

索引任务绑定具体 version_id。执行索引时只读取该版本的 snapshot_json，不会重新读取当前草稿。

如果索引失败，旧的当前生效版本保持不变。只有索引成功后，新版本才会切换为当前生效版本。

## 10. 人工锁管理怎么用

人工锁表示某个会话已转人工，AI 不会自动继续回复。

使用步骤：

1. 进入“人工锁管理”。
2. 先选择店铺。
3. 查看该店铺的 pending_human 列表。
4. 可以按 buyer_id 或 session_id 搜索。
5. 点击单条“解除人工锁”，或在确认后批量解除当前店铺的人工锁。

解除人工锁只修改本地 pending_human 状态，不会发送消息给买家，不会调用 LLM/Ollama/pgvector。

批量解除只作用于当前 shop_id，不会影响其他店铺。

## 11. 试聊调试怎么用

“试聊调试”用于 no-send 测试 AI 回复。常用方式：

1. 选择店铺。
2. 输入 buyer_id。
3. 如需测试商品问题，填写 goods_id 和 goods_name。
4. 选择调试模式：
   - facade：安全模拟，不调用真实 provider。
   - real_engine_only：走真实 InternalEngine，但不调用真实 provider。
   - real_full：调用真实 LLM/Ollama/pgvector，但仍然 no-send。
5. 输入买家消息，点击“发送测试消息”。
6. 查看右侧 trace，确认商品上下文、RAG 命中、active version、LLM 和 guardrail 状态。

real_full 会调用真实服务，但不会发送 PDD 消息。

## 12. 服务状态怎么看

“系统设置”会显示：

- InternalEngine 是否就绪。
- PgVector 是否配置。
- Ollama 是否配置。
- LLM 是否配置。
- no-send 是否启用。
- PDD 真实发送是否关闭。

页面只显示安全摘要，不展示真实密钥、token、cookie、授权头或 DSN 密码。

## 13. 常见问题

### 保存草稿后为什么 AI 没有用新内容？

草稿不会立即生效。必须发布生成版本快照，并完成索引任务。索引成功后才会成为当前生效知识。

### 发布后为什么还没生效？

发布只生成版本和待处理索引任务。请检查索引任务是否成功。

### Fake index 和 Real index 有什么区别？

Fake index 用于测试状态流，不写 pgvector。Real index 会调用 embedding 服务并写入 pgvector。

### 试聊页面会不会给买家发消息？

不会。试聊页面是 no-send 调试入口。

### 解除人工锁会不会通知买家？

不会。解除人工锁只改变本地状态。

## 14. 什么操作不会发送 PDD

- 查看数据总览。
- 查看店铺和商品知识。
- 保存 SOP 草稿。
- 保存商品人工知识。
- 发布 SOP 或商品知识。
- 执行索引任务。
- 查看版本和索引任务。
- 试聊调试。
- 查看 trace。
- 解除人工锁。

## 15. 什么操作会影响 AI 真实回复

以下操作在索引成功后会影响 AI 后续检索到的知识：

- SOP 发布并索引成功。
- 商品人工知识发布并索引成功。
- 当前生效版本切换。
- 解除人工锁后，该会话后续可能重新由 AI 自动回复。

## 16. 发布前检查清单

- no-send 状态符合预期。
- PDD 真实发送链路由既有服务控制。
- Provider 状态已确认。
- 商品知识覆盖率无异常。
- 关键 SOP 已发布并索引成功。
- 关键商品人工知识已发布并索引成功。
- 试聊调试能命中当前生效版本。
- 人工锁列表已检查。
- 调试日志无大量失败。

## 17. 发布后观察指标

- reply_sent 数量。
- pipeline_skip 数量。
- pending_human 数量。
- answer_generation_status=ok 比例。
- RAG hit count 和 active version 命中情况。
- guardrail blocked 数量。
- LLM/Ollama/pgvector 错误数。
- 单店和多店 worker 运行状态。
- 买家连续短句是否被正确合并处理。

## 18. 店铺接入怎么用

“店铺接入”用于给新店铺完成登录授权、商品同步、接入验收和 AI 启用确认。当前统一使用远程浏览器登录，适合短信验证码、滑块、扫码和平台安全验证。

使用步骤：

1. 进入“店铺接入”。
2. 填写店铺名称和 PDD 账号，密码可留空并在远程浏览器中输入。
3. 点击“创建远程浏览器登录会话”。
4. 在页面下方远程浏览器中完成 PDD 登录、短信验证码、滑块、扫码或安全验证。
5. 登录成功后点击“我已完成登录，检查状态”，页面会显示授权状态和绑定到的 shop_id。
6. 进入“同步商品”，先用少量商品同步验证授权和商品接口。
7. 进入“初始化知识”，根据商品覆盖率补 SOP 和商品人工知识。
8. 进入“接入验收”，按推荐问题完成试聊调试，然后点击“我已完成试聊并确认通过”。
9. 进入“启用 AI”，确认 checklist 通过后再点击启用。

安全说明：

- 密码只用于当前登录会话，不保存。
- cookie/token 会加密保存，不会在页面或 API response 中展示。
- 创建登录会话、远程浏览器登录、商品同步、接入验收都不会发送 PDD 消息。
- 启用 AI 只修改该店铺的 AI 配置状态，不会直接启动 worker，也不会立即发送消息。
- 如果 checklist 未通过但确需强制启用，必须填写原因；该操作会记录审计日志。
- 当前 worker 状态只读展示，不在 Web 后台自动启动或停止 worker。

## 19. 接入验收 checklist

接入验收会检查：

- 店铺授权是否有效。
- 商品同步是否完成。
- 商品知识覆盖率是否有价格和规格。
- Knowledge Center 是否已有 active version。
- no-send 试聊是否已经确认通过。
- 服务状态是否可查看。
- Worker 状态是否可读。
- 人工锁管理是否可用。

必填项全部通过后，页面才会允许普通启用 AI。非阻塞项会显示警告，运营可以继续补齐。

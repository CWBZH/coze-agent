# V3.0 范围定义

## 版本信息
- 文档版本: 1.0
- 创建日期: 2026-05-12
- 目标架构: Prompt-First 轻量架构

## 1. V3.0 目标

### 1.1 核心目标
将现有客服助手重构为"轻量级本地客服助手 3.0"，采用以下技术路线：
- **商品 JSON 精准注入**：锁定当前商品 goods_id，直接注入结构化 JSON
- **强 Prompt 约束**：明确禁止行为和回复规范
- **低温度本地 LLM**：使用 temperature=0.0-0.1 的本地模型（customer-service:latest，qwen2 family，约 3.1B，F16）
- **回复后校验**：发送前执行规则校验，拦截高风险回复

### 1.2 解决的问题
| 问题 | V2.0 现状 | V3.0 方案 |
|------|-----------|-----------|
| 复杂 slot 主链路 | 依赖 LangGraph 状态机 + 多级路由 | 移除主链路，简化为商品定位 + JSON 注入 |
| Qdrant 依赖 | 向量检索决定回复内容 | 仅保留为离线评测/未来扩展，MVP 不依赖 |
| 向量相似度阈值 | score >= 0.55 通过率仅 7.5% | 不依赖向量相似度，避免阈值调优负担 |
| 商品字段缺失 | LLM 容易从标题推断编造 | Prompt 明确要求"缺失字段必须表达不确定" |
| SKU 原文漂移 | LLM 改写 SKU 描述 | 校验器拦截 SKU 改写 |

## 2. 明确不做的事情

### 2.1 不做复杂 slot 主链路
- **不维护**：V2.0 的三级路由漏斗（规则引擎 → 语义路由 → LLM 决策）
- **不维护**：SubIntentType 的 17 种细分子意图
- **不依赖**：Qdrant 向量检索作为 MVP 主链路

**理由**：当前测试结果显示，Prompt-only 方案在四款商品上效果良好（单轮 83%，多轮 83%），无需复杂路由。

### 2.2 不做训练模型
- **不训练**：不针对客服场景训练专属模型
- **不微调**：使用现成本地模型 customer-service:latest

**理由**：避免训练数据收集、标注成本和模型维护负担。

### 2.3 不做多轮追问状态机
- **不实现**：复杂的多轮追问状态管理
- **不维护**：会话级别的追问上下文状态机

**理由**：MVP 阶段用短历史（最近 2-3 轮）足够，复杂状态机收益不明显。

### 2.4 不让 Qdrant 决定事实
- **不移交事实判断**：商品字段、价格、规格等事实由 MySQL 商品表决定
- **不用向量相似度过滤**：不依赖 score 阈值决定是否回答

**理由**：向量相似度阈值调优困难（当前评估显示 score >= 0.55 通过率仅 7.5%）。

## 3. MVP 范围

### 3.1 支持的商品
固定四款商品，用于回归测试：
1. `946901558797` - 净爽止汗喷雾保湿除臭净味爽身清新舒爽温和腋下止汗香体20ml
2. `943269377110` - 脖子身体懒人素颜霜提亮全身持久防水润肤不脱防蹭上衣假白学生
3. `942041658034` - 【好物爆款】颜里烟酰胺身体素颜霜免卸防水防汗美白遮瑕持久男女
4. `941078657140` - 60张眼唇卸妆巾温和面部刺激深层清洁便携一次性湿巾孕妇懒人抽取

### 3.2 支持的查询类型
| 查询类型 | 示例 | 数据源 |
|---------|------|--------|
| 商品属性 | "这个有香味吗？" | 商品 JSON |
| SKU 规格 | "有几种规格？" | 商品 JSON |
| 使用方法 | "怎么用？" | 商品 JSON |
| 使用时长 | "一瓶能用多久？" | 商品 JSON |
| 适用人群 | "孕妇能用吗？" | 商品 JSON |
| 售后政策 | "能退吗？" | 客服知识库（非向量检索） |
| 物流信息 | "几天能到？" | 客服知识库（非向量检索） |

### 3.3 边界场景
- **空字段**：商品 JSON 中字段为空时，回复"这个信息我不确定，建议您咨询人工客服"
- **风险问题**：医疗、绝对承诺等问题，回复标准化兜底模板
- **人工请求**：包含"人工"、"客服"等关键词，转人工或提示联系方式

## 4. 成功标准（初始目标）

### 4.1 功能指标（初始目标）
- **单轮准确率** >= 80%（四款商品平均）
- **多轮准确率** >= 75%（最近 3 轮历史）
- **SKU 原文保持率** >= 95%（校验器拦截改写）
- **空字段兜底率** = 100%（不允许编造）

### 4.2 安全指标（初始目标）
- **医疗绝对承诺拦截率** = 100%
- **价格优惠推断拦截率** = 100%
- **人工请求识别率** >= 95%

### 4.3 性能指标（不做硬性承诺）
- 延迟受本地 LLM 性能影响，MVP 阶段不设硬性阈值
- 目标：首字响应 < 3s（实测后调整）

### 4.4 可维护性
- 商品新增：仅修改商品表，不改 Prompt 合同
- 校验规则新增：仅修改校验器规则配置
- 兜底模板修改：不改代码，仅改配置

## 5. 架构边界

### 5.1 数据流
```
用户消息 → 商品定位（goods_id） → 商品 JSON 注入 → LLM 生成 → 校验 → 发送/兜底
```

### 5.2 依赖组件
| 组件 | 用途 | MVP 状态 |
|------|------|----------|
| MySQL | 商品表、客服知识表 | 必须 |
| Redis | 会话历史、商品锁定记忆 | 必须 |
| Ollama | 本地 LLM 推理 | 必须 |
| Qdrant | 向量检索 | 离线保留，不参与 MVP 主链路 |

### 5.3 代码边界
- **保留**：Agent/CustomerAgent/custom/customer_agent.py 的会话管理逻辑
- **保留**：database/product_sync.py 的商品同步逻辑
- **保留**：services/knowledge_sync_service.py 的知识库同步服务
- **新增**：Response Validator 校验器
- **新增**：Prompt Builder（基于 MessageBuilder 重构）
- **移除**：V2.0 的三级路由逻辑（不删除代码，仅注释或配置禁用）

## 6. 风险与约束

### 6.1 已知风险
| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| SKU 原文漂移 | 回复不符合商品实际 | 校验器拦截改写 |
| 字段缺失时从标题推断 | 编造事实 | Prompt 明确禁止，校验器检查"不确定"表达 |
| 风险问题表达不稳定 | 医疗绝对承诺 | 兜底模板 + 校验器双保险 |
| Token 消耗随商品增长 | 成本增加 | MVP 四款商品可控，未来可升级架构 |

### 6.2 约束条件
- 本地模型固定为 customer-service:latest（qwen2 family，约 3.1B）
- MVP 只支持拼多多平台（platform 固定为 `pdd`）
- MVP 不支持多商品对比（如"这两款哪个好"）

---

## 7. 后续演进

### 7.1 短期（MVP + 1）
- 商品数量增长到 10+ 时，引入候选召回（规则 + 向量）
- 支持多平台（淘宝、抖音）

### 7.2 中期
- 引入 LLM 分类器做意图细分
- 支持多商品对比

### 7.3 长期
- 训练专属客服模型
- 支持语音、图片多模态
